# 词境 WordScape 下一阶段执行计划

> 创建时间：2026-07-27  
> 文档定位：172 篇内置课程完成后的产品化执行基准。后续开发按本文档顺序推进，每完成一个阶段先更新状态和验收记录，再进入下一阶段。  
> 当前目标：从“功能和内容均可演示”推进到“数据可信、工程稳定、可邀请真实用户内测”。

## 一、当前基线

截至 2026-07-27，项目已有：

- 7 套内置课程、172 篇文章：
  - 小学 5 篇
  - 初中 18 篇
  - 高中 34 篇
  - 四级 45 篇
  - 六级 22 篇
  - 日常高频 20 篇
  - 职场商务 28 篇
- 172 篇文章均包含英文标题和中文标题。
- 阅读器支持目标词高亮、全文单词点击查词、三种中文模式、单句与连续朗读。
- 已有读后小测、生词本、继续阅读和生成课程流程。
- 前端 lint/build 与后端编译检查通过。
- 当前完整词典只有 1,775 条，尚未覆盖全部课程正文。

当前核心问题不是继续堆叠功能，而是：

1. 全文查词交互已经开放，但词典数据覆盖不足。
2. 内容通过结构化质检，不代表故事多样性、翻译质量和分级难度已经合格。
3. 生成脚本依赖“文件非空即完成”，缺少可靠的断点、清单和原子写入。
4. 缺少覆盖核心用户链路的自动化测试。
5. Supabase 密钥轮换、RLS、同步和正式部署尚未完成。

## 二、执行原则

1. **先保证数据可信，再增加增长功能。**
2. **所有长任务必须可恢复。** 不能因为一次 429 或进程退出重跑整套数据。
3. **验收必须量化。** 不用“看起来完成”作为完成标准。
4. **正式产物与临时状态分离。** 前端课程、正式词典可入库；待生成清单、临时分片和日志不入库。
5. **自动检查先于人工抽查。** 自动检查筛出异常，人工把时间用于语言和学习体验。
6. **外部依赖设置明确关卡。** 密钥轮换、数据库、部署等需要用户权限的步骤不得假设完成。

## 五、阶段 1：词典与生成流水线

### 1.1 以正文实际用词为准建立缺词清单

- [x] 扫描 172 篇正文全部英文 token。
- [x] 统一小写、标点、所有格和词形还原。
- [x] 排除数字、明显人名及无意义 token。
- [x] 与现有词典合并比较，输出确定性的缺词清单。
- [x] 报告目标词覆盖率、正文唯一词覆盖率和按出现次数计算的覆盖率。

验收标准：

- 缺词清单顺序稳定，重复执行无无意义 diff。
- 专有名词与真正缺词分开统计。

### 1.2 修复词典断点续跑

- [x] 不再用文件大小判断完成状态。
- [x] JSON 为空或词条数不符合预期时必须继续。
- [x] 每批成功后原子写入 checkpoint。
- [x] 已有词条与新词条合并，不能覆盖丢失。
- [x] 支持 `--base-url`、`--api-key`、`--model`、`--concurrency` 和 `--retries`。
- [x] 对 429/冷却增加退避等待。
- [x] 最终输出缺失词和失败批次。

验收标准：

- 人工中断后重跑，只生成剩余词。
- 空占位 JSON 不会被误判完成。
- 失败批次不会破坏已经生成的词条。
